# 0003 - SGF 高级语义与多棋谱导入

**Status:** accepted
**Date:** 2026-08-26
**Spec:** SGF FF[4]、用户导入兼容要求
**Deciders:** 用户、Codex

## Context

现有模型只保存棋盘落子，导入器会忽略 SGF 设置局面、过手和同文件中的后续顶层棋树。把设置棋子伪造成普通着法会破坏手数、轮次、分支和导出；把多个顶层游戏树合成变化则会混淆多盘独立棋谱。

## Decision

- `RecordNode` 增加可选的 `setup` 与 `passPlayer`，分别表示 SGF `AB/AW/AE/PL` 和 `B[]/W[]`。
- 设置局面不计手数；过手计手数、切换行棋方但不改变棋盘。
- SGF Collection 中的每个顶层 GameTree 导入为独立 `GameDocument`，由棋谱库批量保存。
- UTF-16 通过 BOM 与空字节模式识别，内部统一为 Unicode 字符串，导出统一使用 UTF-8。
- 当前产品保持固定十五路；非 `SZ[15]` 文件明确拒绝，不做有损缩放或居中映射。
- JSON 只通过可验证的适配器转换；不猜测缺少坐标体系或棋盘尺寸的任意数组。
- 大型 RenLib 继续流式解析；内容签名只读取文件前缀，禁止为了识别格式读取完整大文件。

## Consequences

- 棋盘计算、下一手、手数、紧凑索引、JSON 校验和 SGF 导出都必须理解新节点语义。
- 旧文档和旧紧凑索引通过可选字段继续兼容。
- 多棋谱文件会在棋谱库中产生多份记录，并共享来源文件名但拥有独立 ID。
- 非十五路文件会得到可操作的错误提示，但不会显示错误棋盘。

## Alternatives Considered

- 把 `AB/AW` 变成开局着法：实现简单，但会造成手数和轮次错误。
- 把多盘棋合并为根节点分支：会把独立对局错误表达为同一局面的变化。
- 动态支持任意棋盘尺寸：需要重写棋盘、规则、题库和算法，不适合本轮兼容修复。
