# 第 67 次模型沟通：最近导入列表与一键重开验收

时间：2026-08-29
发送方：GPT
状态：已完成

## 本次目标

完成产品计划 P1-14“最近导入列表”：

- 导入面板顶部显示最近 5 个来源文件。
- 记录成功导入的棋谱和题库文件。
- 刷新页面或打开新页面后仍能显示记录。
- 点击记录可以一键重新打开文件。
- 不让最近导入功能阻塞或破坏正式导入流程。
- 对大型文件设置存储边界，避免自动复制过大的 LIB/DB 文件。

## 当前判断

功能已直接合入当前网页版。最近导入记录使用独立 IndexedDB 数据库保存，不占用棋谱库和题库的业务数据结构。小于等于 16MB 的文件保存本地副本，可以一键重开；超过 16MB 的文件只保存名称、大小和类型，点击时提示重新选择原文件。

重开棋谱时沿用现有产品行为：先恢复完整棋谱，再从根局面打开；用户可以点击“到最后一手”查看完整主线终点。重复导入不会创建重复棋谱，现有导入去重逻辑保持不变。

## 已完成

### 1. 最近导入数据层

新增 `src/recent-imports.ts`：

- 独立数据库：`banbu-gomoku-recent-imports`。
- 独立对象仓库：`files`。
- 最多保留 5 条记录，按单调递增导入时间排序。
- 保存文件名、类型、大小、导入类型和导入时间。
- 小文件保存 Blob 副本；大文件只保留元数据。
- 同名、同大小、同类型导入时，用最新记录替换旧记录。
- IndexedDB 不可用或配额不足时，正式导入仍继续完成。

### 2. 导入流程接入

- RenLib `.lib` 成功打开后加入最近列表。
- DP/DB 数据库成功打开后加入最近列表。
- 普通 SGF/JSON/POS 等棋谱成功导入后加入最近列表。
- 批量导入按来源文件去重后记录。
- 题库 JSON 成功导入后加入最近列表。
- 图片识谱不自动复制图片文件到最近列表，避免与棋谱/题库重开语义混淆。

### 3. 导入面板 UI

- 导入面板新增“最近导入”区域。
- 每条记录显示“谱/题”类型、文件名和可用状态。
- 文件名过长时省略显示，但完整名称保留在 `title` 和无障碍名称中。
- 可用记录显示“可一键重开”。
- 超过存储边界的记录显示“文件较大，请重新选择”。
- 支持深色主题下的面板、边框和类型图标样式。

### 4. 一键重开

- 点击最近记录后从 IndexedDB 读取 Blob。
- 还原为 `File` 对象并重新走正式导入入口。
- 复用现有草稿保护、格式识别、去重、解析、保存和错误提示。
- 读取失败或记录只剩元数据时明确提示重新选择原文件。

## 未解决问题与边界

- 最近列表只保证最近 5 条，不是完整导入历史。
- 超过 16MB 的文件不会被自动复制；大型 LIB/DB 仍需重新选择原文件。
- 浏览器清理站点数据后，最近导入副本也会被清理，这是本地浏览器存储的正常行为。
- 最近记录不保存用户选择的棋谱当前节点，因此棋谱重开默认从根局面开始。
- 图片识谱来源不加入该列表；如后续需要图片重开，应单独设计图片缓存和隐私/容量策略。
