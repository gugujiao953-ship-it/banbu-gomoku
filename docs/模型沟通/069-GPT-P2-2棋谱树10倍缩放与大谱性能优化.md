# 069-GPT-P2-2 棋谱树 10 倍缩放与大谱性能优化

日期：2026-08-29

## 本轮变更

- 缩放范围从 65%–180% 扩展为 65%–10×。
- 增加原生 range 滑杆，支持精细调整缩放比例。
- 增加 2×、5×、10×快捷倍率；加号在高倍率下使用更大的步进，避免需要点击几十次。
- 保留重置视图，重置为 100%。
- 缩放高于 100% 后仍使用画布拖拽查看树，不强行把完整内容塞进手机屏幕。
- 修复 390px 窄屏下滑杆和快捷倍率导致的工具栏横向溢出，改为两行网格布局。
- 节点手数从 SVG 渲染阶段的 `depthOf` 重复计算改为构建可视窗口时计算 `turnDepth`，减少频繁缩放/拖拽时的重复遍历。

## 大谱是否会卡

当前策略不会因为棋谱总节点数很大而一次性卡死：

1. 紧凑大型棋谱只读取当前路径和每个路径节点前 12 个直接子节点。
2. 棋谱树可视窗口有 240 个节点预算。
3. 不使用 `Object.keys(document.nodes)` 枚举百万级懒加载节点。
4. 缩放和拖拽只改变 SVG 变换状态，不重新读取棋谱窗口。
5. 分支节点只显示后续数量，点击后交给现有导航继续按需加载。

因此，大谱的内存和渲染成本主要取决于当前窗口，而不是完整棋谱规模。若一次窗口包含 240 个 SVG 节点，移动端仍会有正常的绘制成本，但不会物化整本棋谱。

## 验收

- `npm run build`：通过，dist 4.85MB。
- `npm test`：191 passed，1 skipped。
- 390×844 浏览器：
  - 点击 10× 后显示 `10×`；
  - range 值为 `10`；
  - 重置后显示 `100%`；
  - 页面宽度 390px，与视口一致，无横向溢出；
  - pageerror/console error 为 0。
- 压力场景：生成 225 条直接分支的 SGF 并导入，树面板只渲染 13 个节点（根节点 + 当前窗口 12 个分支），导入到打开树约 1.3 秒，页面错误 0。

## 后续边界

10× 是当前交互上限。更高倍率如果有必要，应优先加入视口中心缩放、自动定位当前节点和“展开此分支”渐进加载，不建议直接放宽全量节点预算。
