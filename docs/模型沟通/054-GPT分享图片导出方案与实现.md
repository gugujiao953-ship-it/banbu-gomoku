# 054｜分享图片导出方案与实现

日期：2026-08-29  
任务：产品改进计划并发序号 6（P1-1 分享图片导出）

## 1. 目标

在现有“导出与分享”面板中增加“分享当前局面”，把用户当前看到的局面生成高清 PNG。网页端可调用系统分享或保存图片；Android 端复用系统文件分享能力。分享不可用时必须可靠降级为 PNG 下载，不能因为平台能力差异阻断导出。

## 2. 第一版范围

导出一张约 1200×1400 的白底分享卡片：

- 顶部：棋谱名称、当前手数、局面说明。
- 中部：当前棋盘，保持当前旋转与镜像方向。
- 底部：黑白棋手、赛事/主题、日期、规则（仅显示已有信息）。
- 可独立选择：手数、坐标、棋盘标注、“半步五子棋打谱”水印。
- 默认选择跟随当前界面的手数和坐标设置；标注与水印默认开启。
- 使用 `viewDocument` 和 `currentId`，因此未提交草稿也按当前画面导出。

“棋盘标注”包括当前节点的用户文字、圆圈、三角、叉号，以及当前可见的 RenLib/DP 原生文字和候选点。以下临时辅助不导出：AI 推荐点、禁手提示、开局候选区域、获胜动画、交互点击热区。

## 3. 交互流程

“导出与分享”面板顶部增加分享图片区块：

1. 用户调整四个开关。
2. 点击“系统分享”：生成 PNG，优先调用支持文件的 Web Share；原生容器可用时调用 Capacitor Share；用户取消分享不显示错误。
3. 平台不支持文件分享时自动保存 PNG，并提示已降级。
4. 点击“保存 PNG”：直接写入已授权的默认导出文件夹；否则使用浏览器下载。

生成期间按钮禁用并显示“正在生成…”。失败时保留面板和选项，显示可理解的错误提示。

## 4. 技术方案

新增独立纯渲染模块 `src/board-image-export.ts`：

- `createBoardShareSvg(...)`：由 `GameDocument + currentId + options` 生成完全自包含的 SVG 字符串，不依赖页面 CSS。
- `renderBoardSharePng(...)`：把 SVG 绘制到高分辨率 Canvas，输出 `image/png` Blob。
- `boardShareFilename(...)`：生成安全、可读、带当前手数的文件名。
- 棋盘位置、手数、标注、星位和方向变换都在纯函数中计算，便于单测。

新增 `src/share-file.ts` 作为平台适配层：

- 优先 `navigator.share({ files })`。
- Capacitor 原生环境把 PNG 写入缓存目录后交给系统分享。
- 不支持或分享失败时由 UI 调用现有下载路径降级。
- 识别 `AbortError` / 用户取消，不把取消当故障。

`src/App.tsx` 只增加选项状态、两个动作函数和面板入口，不改现有棋盘组件或棋谱格式导出逻辑。样式集中追加到 `src/styles.css`。

## 6. 关键边界

- SVG 所有颜色、字体、描边和阴影均内联，避免导出空白或丢样式。
- 中文使用系统字体栈；绘制失败必须回退下载 SVG 所生成的错误提示，不静默成功。
- `GameDocument.metadata.boardSize` 支持现有 5–25 路范围。
- 空盘、设置局面、过手和有分支的局面都可导出。
- 大型 LIB/DP 只表达“当前可见局面”，不声称导出整个数据库。
- 分享文件在缓存目录中使用临时名称，不触碰签名和用户永久数据。

## 7. 验收标准

1. 含黑白棋、手数、坐标、四类用户标注的局面能生成可打开的 PNG。
2. PNG 尺寸固定、内容不裁切，中文标题和白棋清晰。
3. 关闭任一选项后，对应内容确实不在 SVG/PNG 中。
4. 旋转 90/180/270 度及镜像后，导出方向与页面所见一致。
5. 系统支持文件分享时能传入 PNG 文件；不支持时自动下载。
6. 用户取消系统分享不报错、不自动重复下载。
7. 未提交草稿中的落子和标注可以导出。
8. `npm test`、TypeScript 检查和 `npm run build` 通过。
9. 320px 窄屏下导出面板可滚动，按钮触控区域不小于 44px。
