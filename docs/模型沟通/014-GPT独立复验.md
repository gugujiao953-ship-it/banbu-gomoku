## 三、阻断项 P0：百万节点以上的分块恢复会打乱节点 ID

### 证据

`src/large-storage.ts:68-82` 中，typed array 分块会按数值 `offset` 排序；但 `ids`、`texts`、`marks` 只是按照 IndexedDB `getAll()` 返回顺序直接追加。

分块 key 形如：

```text
record:ids:0
record:ids:250000
record:ids:500000
record:ids:750000
record:ids:1000000
```

IndexedDB 按字符串 key 排序，`1000000` 会排到 `250000` 前面。结果是 `ids` 与 `parent/moveCode/state/textRefs` 等 typed arrays 不再处于同一节点下标。

新增独立黑盒：

```text
node qa/chunk-order-blackbox.mjs
```

1,000,001 节点实测：

```text
index 0:       root-test -> root-test              正确
index 250000:  renlib-test-5cwg -> renlib-test-lfls 错误
index 500000:  renlib-test-apsw -> renlib-test-apsv 错误
index 750000:  renlib-test-g2pc -> renlib-test-g2pb 错误
index 1000000: renlib-test-lfls -> renlib-test-lflr 错误
matches: false
```

这不是显示问题，而是大型棋谱从 IndexedDB 恢复后的节点身份和棋步数据错配。现有《松月》黑盒刷新后只检查标题与 DOM 数量，没有检查刷新后的深层节点、文本和父子关系，所以产生了假通过。

### 必须修复

- `ids`、`texts`、`marks` 分块必须和 typed arrays 一样按数值 `offset` 排序/定位后组装。
- 最好不要依赖 `getAll()` 的 key 顺序；按 `offset` 写入目标数组位置。
- 新增 `>1,000,000` 节点 round-trip 回归，至少检查 0、250000、500000、750000、1000000 边界及其前后位置。
- 《松月》刷新验收必须检查真实导航、父子关系、坐标、注释/boardText，而不只是标题。

## 四、阻断项 P1：新显示模型是孤立代码，没有接入产品

### 源码证据

`src/renlib-display.ts` 定义了 `rawText/rawMark/rawColor/semantic/displayKind`，但全项目搜索显示：

- 业务代码没有 import 或调用 `renLibDisplayMark()`；
- `RecordNode` 和 `CompactRenLibIndex` 没有保存 `RenLibDisplayMark`；
- RenLib 解析器仍只保存 `boardText` 和 `renLibMark: boolean`；
- 棋盘渲染不读取 `displayKind/rawColor/rawMark`。

`src/App.tsx:154-164` 仍对每个变化无条件绘制：

```tsx
<circle className="renlib-variation-dot" />
{node.boardText && <text className="renlib-variation-label">...</text>}
```

因此新增的 8 个映射断言只是独立函数单测，不能证明“原谱解析 → raw 数据保存 → compact round-trip → 按原样渲染”成立。

### 真实浏览器证据

新增独立黑盒：

```text
node qa/renlib-display-blackbox.mjs "D:\五子棋\定式谱\雨.lib"
```

在《雨》的第一个真实分支：

- `G9`：无文字，显示白色圆点；
- `I9`：原始文字为 `#`，但仍先显示白色圆点，再叠加文字；
- 文字实际字号为 `7px`；
- 控制台错误 0。

截图：`artifacts/renlib-display-rain-412x915.png`。手机尺寸下 `#` 几乎不可辨认，和用户要求“原谱文字直接显示、去掉圆框、11–13px 可读”不符。

### 必须修复

- 从 RenLib 解析器开始保存 raw 信息，贯通普通节点、compact index、IndexedDB 和 lazy materialize。
- 文字类 `displayKind=text` 不画底层圆点/圆框，使用可读字号与描边。
- 黑点、白点、蓝点必须由原谱显示字段决定，不能用下一手棋子的 `player` 颜色替代。
- 未确认的二进制语义保留 raw 值，不可伪造；但 raw 字段不能只存在于从未调用的 helper 中。
- 增加真正的集成/浏览器测试：a、c、ccc、普通文字、黑/白/蓝、无标签、27+ 分支和已落子遮挡。

## 五、性能仍未达严格目标

《松月》本轮数据：

```text
总导入时间：67036.5ms
Worker parse：44056.8ms
Long Tasks：27 次
最大 Long Task：8100ms
前进导航：p50 17.9ms，p95 67.8ms，max 91.2ms
后退导航：p50 16.3ms，p95 38.5ms，max 72.6ms
```

两个明确热点：

1. `createLazyDocument()` 每次创建/恢复文档都在主线程扫描全部 22M 节点重新统计 branchCount（`src/compact-index.ts:245-254`），而解析器已经算过同一统计值。
2. `compactNodeIndex()` 使用 `index.ids.indexOf(id)`（`src/compact-index.ts:274-278`），Board 和分支面板在导航渲染时调用，对 22M ID 是 O(n)。

应把 parser stats/branchCount 随 compact index 持久化，并为数字/base36 RenLib ID 提供 O(1) 下标解析或映射，避免每次导航线性搜索。
