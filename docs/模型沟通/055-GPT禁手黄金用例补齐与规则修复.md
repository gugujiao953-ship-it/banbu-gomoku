## 2. 黄金用例分组

1. 恰五：横、竖、主对角、副对角四个方向。
2. 长连：横、竖、主对角、副对角四个方向。
3. 四形：单活四合法；横竖异向四四；横线与斜线异向四四；同一横线两个独立冲四。
4. 三形：直三交叉三三；两个跳三交叉三三；白子封端假活三；边界无双端成四空间。
5. 延伸点合法性：延伸点形成长连、四四或三三时，不得把原形计为活三。
6. 优先级与接口：恰五优先、长连优先、占点拒绝、复用棋盘缓存失效、禁手点不含占点、黑白胜线规则差异。

## 3. 测试发现并修复的真实缺陷

原实现判断活三延伸点是否合法时，只排除了长连和四四。若唯一能形成双端直四的延伸点本身是三三禁手，原局面仍会被错误累计一个活三，可能进一步误判为三三禁手。

`src/game.ts` 的最小修复：

- 只对确实能形成“双端直四”的候选延伸点做后续合法性检查。
- 在长连、四四之外，增加延伸点三三检查。
- 恰五延伸仍按合法胜着优先处理。
- 嵌套检查限制为一层，用于解决直接延伸点漏判，同时避免禁手扫描和 VCF 搜索递归膨胀。

初版修复曾使 VCF/AI 预算测试超时。定位后将嵌套检查收窄到真正形成活四的点，专项回归恢复通过；没有提高测试预算或放宽断言。
