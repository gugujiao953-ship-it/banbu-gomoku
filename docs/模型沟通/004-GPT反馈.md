## 本轮必须完成的任务

### 1. 暴露真实分叉节点诊断信息

在 compact index 层增加只读诊断能力，至少返回：

- 第一个 childCount > 1 的 nodeIndex。
- 该节点的 nodeId。
- parent nodeId。
- depth。
- childCount。
- 前 10 个直接子节点的 nodeIndex、nodeId、坐标和颜色。
- 是否存在多个非空后续分支。
- 该节点所在主线路径。

建议 API：

    findFirstBranchNode(document)
    inspectBranchNode(document, nodeIndex)

如果已有相近 API，直接复用，不要重复实现。

诊断信息必须只读取索引，不得调用 Object.keys(document.nodes) 或 Object.values(document.nodes)。

### 2. 改造黑盒测试为真实分支测试

qa/large-lib-blackbox.mjs 必须：

1. 导入或打开松月.lib。
2. 通过页面可访问的测试接口、开发模式接口或预先生成的诊断 JSON 获取真实分叉 nodeId。
3. 直接让应用跳到这个节点。
4. 点击“变化”。
5. 断言面板文案中的总变化数等于 compact index 的 childCount。
6. 断言真实分支行数大于 0。
7. 断言第一行显示正确的坐标。
8. 滚动或改变窗口后，断言窗口内容发生变化。
9. 点击一个不是当前主线的兄弟分支。
10. 断言 current node 已切换到目标 child。
11. 继续前进至少一步，断言子分支仍然存在。
12. 跳到叶节点，再打开变化面板，断言能看到父分叉点的兄弟变化。

如果不希望在生产页面暴露测试接口，可以采用以下方式之一：

- 在测试构建中启用 window.__RENJU_DEBUG__。
- 通过 URL 参数启用诊断模式。
- 生成一个只读 fixture 页面。
- 在页面添加不影响用户的测试专用 data 属性。

不要为了测试而使用无法复现的人工点击路径。

### 3. 增加树完整性强断言

为真实分叉节点增加断言：

- node.children.length === compact childCount。
- 每个 child.parentId === branchNode.id。
- child 坐标与 compact index 中的坐标一致。
- child 顺序一致。
- 分支面板显示数量准确。
- 点击分支后 currentId 与目标 childId 一致。
- 默认主线设置前后，子节点集合不改变。

### 4. 输出松月.lib 完整统计

不能再通过：

    Object.keys(document.nodes)
    Object.values(document.nodes)

来统计松月.lib。

要求在 Worker 解析或 compact 构建阶段直接输出：

- nodeCount。
- edgeCount。
- branchNodeCount。
- maxChildren。
- maxDepth。
- warningCount。
- importMs。
- compactBuildMs。
- indexedDbWriteMs（如果可以测量）。

如果当前 RenLib 解析阶段仍然先创建 GameDocument.nodes，请至少在解析过程中同步统计，避免浏览器侧再次枚举整个对象树。

### 5. 补导出再导入验证

建立一个真实分支回归流程：

1. 定位真实分叉节点。
2. 获取至少 3 个兄弟变化。
3. 导出 SGF。
4. 重新导入 SGF。
5. 对比节点数、边数、最大深度和分支节点数量。
6. 对比随机抽样的坐标、父子关系和注释。
7. 如果 RenLib 特有字段无法由 SGF 表达，报告具体损失。
