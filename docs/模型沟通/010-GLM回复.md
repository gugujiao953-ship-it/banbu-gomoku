## 一、项目背景

半步五子棋打谱是一个 React + TypeScript + Vite 的移动优先五子棋打谱工具，核心目标是让网页版能够像桌面软件一样流畅地打开大型 RenLib 定式库（雨.lib、松月.lib），支持主线、分支、标注和导航，且不因为文件规模大而卡死或丢失分支。

## 二、核心改造历程

### 2.1 约 10 轮并发改造

#### 第一轮问题发现

- 普通 JS 对象 `document.nodes[id] = RecordNode` + `children[]` 碰到 V8 的 "Too many properties to enumerate" 限制，2200 万节点直接崩溃。
- 分支面板一次性读取所有子节点，DOM 过大。
- 查找功能在 React render 中执行 `Object.values(document.nodes)`，全量 2200 万节点物化。
- Worker 把完整 `GameDocument.nodes` 通过 `postMessage` 回传主线程，结构化克隆报 "out of memory"。
- 导航 `boardAt()` 每次沿根路径重放，深树偶发长任务。
- 自动保存 `saveToLibrary()` 对 lazy document 做 `JSON.stringify`，触发 `RangeError: Too many properties to enumerate`。

#### 逐步解决的架构问题

| 问题 | 解决方式 |
|---|---|
| 普通对象属性上限 | 用 `Map<string, RecordNode>` 替代普通对象，后续改为 `Map` + 整数索引，最终改为列式数组直接解析，彻底跳过中间对象树 |
| Map 节点数量上限 | 去掉 string ID 的 `Map<string, number>` 索引，改为整数 nodeIndex |
| Worker structured clone OOM | 改为 `postMessage` 只发 typed-array buffer + transferable 参数 |
| 全量 `Object.values(document.nodes)` | 查找改为 `compactSearch()` 直接扫描 compact 索引 |
| 分支面板 `children.slice()` 前缀物化 | 改为 `compactChildWindow()` 从 firstChild/nextSibling 直接读取窗口 |
| 棋盘变化点全量读取 | 改为 `compactChildWindow` 最多 513 个 |
| 导航 `boardAt()` 路径重放 | 增加父节点棋盘增量缓存 |
| `mainLineLength` 深链递归 | 对 compact 文档直接返回 `"大型"` |
| `saveToLibrary` 全量枚举 | 对 compact 文档跳过 `saveToLibrary`，直接标记已保存 |
| `createLazyDocument` 建立 2200 万 Map | 改为解析 base36 数字后缀，不再创建 Map |

### 2.2 当前解析器架构（最终版）

```
RenLib 流
→ 列式数组解析（RenLibArrayBuilder）
→ ids (number[])
→ parent / firstChild / nextSibling / lastChild / childCount / preferredChild
→ moveCode / anchorCode / state / textRefs / evaluation / markRefs
→ 字符串池去重（Map<string,number>）
→ 直接生成 CompactRenLibIndex（typed arrays）
→ Worker transferable buffer 发送
→ 主线程 createLazyDocument()
→ 分块 IndexedDB 持久化
→ 需要时按需物化节点（lazy proxy）
```

不再使用：

- 普通 `document.nodes` 对象
- 每节点 `RecordNode` 中间树
- 每节点 `children[]` 数组
- 节点 `Map<string, number>`
- 完整 `GameDocument` 结构化克隆
- `localStorage` 全量枚举
- `JSON.stringify` 大文档

### 2.3 分支面板架构

```
compactChildWindow(index, nodeIndex, start, end)
→ firstChild → nextSibling 链（O(窗口大小)）
→ 固定窗口虚拟列表
→ 不物化 2200 万兄弟
→ 不按"加载更多"累积 DOM
→ 叶节点自动切到父节点展示兄弟
```

## 三、已修复的断裂问题清单

| 问题 | 现象 | 解决阶段 |
|---|---|---|
| V8 对象属性上限 | `Too many properties to enumerate` | Map→列式数组 |
| Map 大小上限 | `Map maximum size exceeded` | 去掉 Map<string,number> |
| Worker clone OOM | `Data cannot be cloned, out of memory` | transferable buffer |
| 全量枚举查找 | `Object.values(document.nodes)` 2200 万次物化 | compactSearch |
| 分支面板前缀物化 | `children.slice(start,end)` 先物化大量兄弟 | compactChildWindow |
| 导航 boardAt 深树 | 偶尔 2 秒级长任务 | 增量棋盘缓存 |
| mainLineLength 递归 | 深链 2200 万节点栈溢出 | compactNodeCount 保镖 |
| localStorage stringify | `JSON.stringify` lazy proxy 全量枚举 | 跳过 saveToLibrary |
| 删除残留 chunk | 分块不清理，IndexedDB 膨胀 | removeLargeDocument 加 cursor |
| 分块恢复丢 marks | 棋盘标注消失 | assembleCompactIndex 加 objectFields |
| 分块 getAll() 全量 | 多谱场景大量无关读取 | IDBKeyRange.bound |
| 刷新恢复栈溢出 | `Maximum call stack size exceeded` | 修复 spread 展开 22M 数组 |
| 导入后控制台错误 | `Cannot read properties of undefined (reading 'children')` | 增加当前节点 fallback |
| 分支面板 undefined 崩溃 | 无法物化时直接访问 children.length | 分支行跳过 null 节点 |
| 数据库版本未迁移 | `index-chunks` store 不存在 | 版本升到 6，事务包含 CHUNK_STORE |
| 自动保存全量扫描 | 保存时调用 fingerprint/mainLineLength | 对 compact 文档保镖 |

## 八、标记语义说明

按用户指定的爱五子棋显示层约定保留：

- `a`：好点 / 推荐变化
- `c`：坏点 / 败点
- `ccc`：c 类坏点
- 黑点：可行 / 推荐后续
- 白点：败点 / 不推荐
- 蓝点：特殊类别

同时保留原始 raw 标记字段，不将未经独立格式文档确认的原始字节含义伪装成 RenLib 官方标准。
