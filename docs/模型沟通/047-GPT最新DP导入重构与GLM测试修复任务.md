## 二、已经完成的根因修复

### 1. DP/DB 按“局面数据库”解析

目标网站的 `.db` 不是普通的棋谱行文件，而是：

```text
局面键 -> 当前局面记录
       -> 当前局面正文注释
       -> @BTXT@ 坐标标注
       -> 子局面对应的下一手/评价
```

最新版 `src/formats.ts` 已经改为：

1. 读取 LZ4 解压后的数据库记录数量。
2. 解析二进制局面键，而不是扫描所有文本坐标并顺序落子。
3. 根据局面键恢复棋盘状态和轮到哪一方走。
4. 从 `@BTXT@` 中恢复坐标标注。
5. 将记录正文挂到对应局面注释。
6. 根据父子局面键建立可导航变化关系。

### 3. RenLib 原生节点标记不再伪造注释

之前 `info & 0x10` 会生成：

```text
renlib-node-mark
```

这会让用户误以为原谱里真的有这段注释。最新版仍然保留 `mark` 类型和原始 flags，但不再填充虚假的文本。

### 4. 注释入口调整

当前 UI 中注释按钮常驻显示：

- 当前节点有注释/原生局面标注时，可以展开内容。
- 当前节点没有内容时，按钮仍存在，但不会展开空面板。
- 棋子右下角的小注释提示仍然只在当前节点确实有内容时显示。
- DP 的局面标注现在会进入当前节点的可见注释内容，不会只留在棋盘内部而让用户误以为丢失。

## 四、发现 bug 时的修复原则

### 1. 先判断是导入层、存储层还是显示层

如果棋盘坐标、父子关系、注释归属不对，优先检查：

- DP 二进制局面键解析。
- 轮到哪一方走的计算。
- 对称归一化和坐标映射。
- 父子局面关系建立。
- `@BTXT@` 的坐标解析。
- Worker 与主线程之间的数据传输。
- compact index 和 IndexedDB 恢复。

不要先改颜色、文案或 `A/L/a/c` 的语义映射。

### 2. 不得丢失未知原始字段

未知 DP 记录、原生标记、正文、局面文字都要保留，不能为了让界面“看起来正确”而静默丢弃。

### 3. 不要用伪造文本修 bug

不要再添加类似以下内容：

```text
原生标记：renlib-node-mark
```

如果只有 flag 没有文本，就保留 flag 状态；如果有原始文本，就显示原始文本。

### 4. 修改后必须加回归测试

修复任何导入问题后，至少补充：

- 一个最小二进制/压缩 fixture 测试。
- 一个真实文件测试或真实文件抽样测试。
- 一个 UI 导航测试。

不能只跑 TypeScript 编译，也不能只检查节点数量大于 0。
