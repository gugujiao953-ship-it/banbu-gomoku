## 一、本轮针对 029 的修复

### 1. 切换门禁改为单层

第 029 次指出旧调用链：

```text
openLargeRecord
  → withDraftGuard
      → openRecord
          → withDraftGuard
```

会导致用户点击“放弃草稿并切换”后再次弹出门禁，并使活动 ID 进入半切换状态。

本轮拆分为：

```text
requestOpenRecord / withDraftGuard
  → performOpenRecord
```

实现：

- `performOpenRecord()` 不执行草稿检查，只负责完成文档、游标、模式、面板和活动 ID 的原子切换。
- `openRecord()`、`openLargeRecord()`、`newRecord()` 只在入口执行一次 `withDraftGuard()`。
- pending action 只调用无门禁的 `performOpenRecord()`。
- `ACTIVE_LARGE_RECORD_KEY` 只在实际完成目标文档切换后写入。
- 取消、目标读取失败或保存失败时不修改活动 ID。

### 2. 保存失败不得继续切换

`commitCompactDraft()` 改为返回明确的 `Promise<boolean>`：

```text
true  = 派生版本提交完成
false = 提交失败，当前草稿与会话保留
```

“保存草稿并切换”按钮只有在返回 `true` 时才执行 pending action；失败时保留门禁、原棋谱、草稿和活动 ID。

### 3. 派生保存和刷新连续性继续保持

保留第 28、29 次已验证的能力：

- 派生版本拥有独立 `document.id`。
- `document.id === active summary.id`。
- 派生版本始终使用 `rootBaseId`，不形成不可加载的二级链。
- 当前游标 `currentId` 写入派生记录，刷新后恢复。
- 从棋谱库打开派生谱后，后续草稿写入派生版本自己的 `documentId`。
