## 一、无限思考无法停止：根因与协议

### 根因

旧实现把“正在思考”的 UI 状态、Rapfi Worker、回退 Worker、分析 Worker 和页面/棋谱切换分别管理：

- 请求没有统一且可验证的 `requestId / generation / contextKey`；旧消息可在新局面到达。
- 部分入口只清 UI 或终止其中一种 Worker；切换棋谱、模式、规则、导入、删除/恢复等路径覆盖不全。
- Rapfi WASM 搜索可能长时间占用 Worker 事件循环，排队的合作式 `YXSTOP` 不保证及时执行。
- 普通“思考”、人机和陪练各有生命周期，重复开始、回退引擎和错误路径容易留下监听器或陈旧回调。

### 现行取消协议

- 复用并行任务提供的 `TaskManager`，没有另建公共任务状态体系。
- `AiWorkerController` 只负责互斥 AI Worker 所有权：每次开始生成唯一 `requestId`、单调 `generation` 和包含棋谱/节点/局面的 `contextKey`。
- Worker 消息必须同时通过当前 Worker 身份、`requestId`、`generation` 和局面上下文门禁。
- 主动取消先发送 `{ type: "stop", requestId, generation }`，随后强制 `terminate()`。合作停止用于协议完整性，强制终止是 WASM 阻塞时停止 CPU 的最终保证。
- Rapfi 失败切换本地 Worker 时保留同一请求身份；旧 Worker 立即终止。正常完成、用户取消和错误分别进入 success/cancel/fail，不把用户停止显示成错误，也不调用“无合法落子”回调。
- 每次正常结束或取消都销毁 Worker；下一次按需新建，避免多个 Worker、监听器或计时器泄漏。

### 已覆盖取消入口

- 点击人机“停止思考”或普通思考按钮；
- 重复开始另一项 AI 任务、开始 VCF 等互斥任务；
- 落子/导航导致局面变化；
- 切换棋谱、棋题、模式、底部页面；
- 新建、导入、图片识谱、删除、永久删除、清空或恢复棋谱/题集；
- 更改人机规则、时限、强度、无限模式、深度、开局、禁手或执棋方；
- 退出人机、组件卸载、`visibilitychange=hidden`、`pagehide`。

不限时搜索在 Rapfi 中使用 `TIMEOUT_TURN 0` 且不设置自动停止定时器；本地回退使用超长预算。两者均由主线程强制终止保证即时停止。有限时长与无限时长共用相同请求门禁和取消路径。

### 应用枚举与实际语义

| 应用规则 | 获胜 | 长连 | 禁手 |
| --- | --- | --- | --- |
| `renju` 连珠 | 黑方恰五；白方五个以上 | 黑方无恰五时为禁手；白方可胜 | 仅黑方：长连、四四、三三 |
| `standard` 标准 | 双方必须恰五 | 合法但不获胜 | 无 |
| `freestyle` 自由 | 双方五个以上获胜 | 合法且获胜 | 无 |

RIF 9.1/9.2 明确：黑方同一手形成恰五时先判胜，即使另一方向同时形成长连、四四或三三。原主规则、VCF 和 AI 搜索曾存在优先级或算法分叉，本轮已统一：

- `game.ts`：恰五先于禁手；standard 只认恰五。
- `vcf.ts`：连珠黑棋直接复用 `evaluateRenjuMove`，不再复制一套“长连先判”的逻辑。
- `renju-ai/engine.ts`：胜负和评估完整传递 `renju / standard / freestyle`；连珠黑棋候选合法性复用主规则判定，修复同方向两个独立四、真/假三等偏差。
- `puzzle-ai.ts` / Worker：完整规则枚举传入搜索，不再用单一 boolean 模糊 standard 与 freestyle。

规则说明仅展示应用真实存在的三种胜负规则和五种开局规则；详细解释长连、四四、三三、活三、冲四/活四、真三/假三、共享棋子、同方向去重、延伸点合法性、恰五优先与提示显示。界面同时明确：复杂禁三只作为实用辅助，不宣称替代正式裁判。

## 三、棋子透明度

- 新存储键：`banbu-stone-opacity-v1`；默认 100%，最低 40%。
- 兼容旧 `renju-note-display-settings-v1` 中的 `stoneOpacity` / `stoneOpacityPercent`；旧配置缺失时保持 100%，升级后视觉不突变。
- 设置页“棋盘与棋子”增加触控滑杆、当前百分比、即时棋盘预览和恢复默认。
- 主棋盘和导出 SVG/Canvas 只给 `.stone-body` 设置透明度；手数、最后一手、胜线、禁手、候选、注释/书签和点击区域均在外层。
- 低透明度时增加独立可见性描边，100% 时描边为 0，不改变既有默认视觉。
- 备份/恢复包含该设置；旧备份缺字段时恢复为 100%。
- 360/390/412px、深色模式、壁纸/材质路径、减少动效和 Android WebView 使用同一 DOM/SVG/CSS 实现。

## 六、剩余风险

1. 为确保取消正确，当前每次 AI 正常完成也销毁 Worker；下一手会重新加载 Rapfi WASM，首步延迟可能高于长期复用 Worker。后续若做池化，必须保留 request/generation/context 门禁，且取消时仍强制销毁。
2. 主规则的禁三实现采用有限递归层级；规则说明已如实标注为实用辅助。正式比赛裁判级覆盖仍需更大的 RIF 黄金题库。
3. Android WebView 共用相同代码路径且 legacy 构建通过，但本轮机器无设备工具，仍建议下一次有真机时复测：不限时开始→停止、切谱、退后台返回、无自动落子/持续耗电，以及透明度与规则说明窄屏显示。
