# 081｜研究棋谱与资料管理工作流

日期：2026-08-30

## 任务结论

本阶段已在不改变棋谱数据语义、不迁移存储格式、不移动棋谱核心、导入解析或 AI Worker 的前提下，完成一组可直接使用的“研究棋谱 + 管理资料”闭环：

1. 自动演示当前变化：播放/暂停、0.5×/1×/1.5×/2×、遇分支暂停或沿主线、循环当前变化。
2. 导出范围明确化：整份棋谱、当前变化、当前局面分别导出，SGF/JSON 文件名和成功提示带范围；原格式直出只允许整谱。
3. 本谱搜索连续核对：查找结果可在面板不关闭的情况下前后跳转，并显示当前序号。
4. 继续研究与最近资料：棋谱库提供“继续上次研究”、最近普通/大型棋谱和草稿状态。
5. 资料筛选：全部、有草稿、近 7 天、大型，可与关键词搜索叠加。
6. 资料安全入口统一：回收站、完整备份、恢复备份集中到同一入口，并明确状态和能力边界。

没有新增棋谱持久化字段。书签继续复用现有“分支书签 + 可重命名标签”能力，未为备注单独扩展 schema，避免在本阶段引入兼容迁移。

## 功能组合选择理由

- 自动演示、分支策略与循环组成完整复盘闭环，直接降低长变化逐手点击成本；逻辑可独立为 hook，不侵入棋谱核心。
- 导出范围是高风险语义点，必须先让用户明确“整谱 / 当前变化 / 当前局面”，再选择格式，避免把局部内容误认为完整备份或原数据库。
- 搜索前后跳转复用现有搜索结果，不改变搜索索引，只补齐连续核对体验。
- “继续上次研究 + 最近棋谱 + 草稿筛选”复用现有活动会话、更新时间和草稿存储，不需要新增数据库版本。
- 回收站与备份原本能力已存在，统一入口比新增另一套安全机制更可靠，也能保持恢复语义一致。

## 架构与兼容边界

- 新逻辑优先放在 src/features/research 与 src/features/library。
- App.tsx 只负责状态编排、已有导航适配和面板接线，没有整体重写。
- 自动演示通过现有普通、分页和动态数据库导航入口前进；动态源仍只使用当前已加载/首选路径。
- 导出继续调用现有 exportSgf、exportJson 和文件落地能力；范围模块只构造临时导出文档，不修改当前棋谱。
- 大型棋谱草稿状态沿用 IndexedDB 检查，并将 effect 依赖收窄为 draftPresent，避免每次草稿操作内容变化都重新扫描所有大型摘要。
- 未引入关键流程动画依赖或缺少 legacy 转译保障的新运行时语法；生产构建仍生成 modern 与 legacy bundle。
- Graphify 架构查询确认 App.tsx/Sheet 仍是编排边界，草稿、存储、动态会话和格式原语保持在原模块；结果已保存到 graphify-out/memory/query_20260830_124836_how_do_app_shell_sheets_connect_to_research_playba.md。

## 风险与边界

- 本任务没有专门拿真实超大型 .lib / DP / DB 文件做播放压力测试；已有 RenLib 资产、百万节点分块顺序和现有导航回归通过。
- 动态数据库的播放按当前已加载路径与首选后续推进，不会承诺遍历尚未加载的完整数据库。
- 动态数据库选择“整份棋谱”时，仍诚实表示当前可见/已加载内容，行为边界与原实现一致。
- 大型资料页需要对每个大型摘要执行一次 IndexedDB 草稿存在性查询；已避免草稿每个操作都重复触发，但大型库首次进入时仍是 O(n) 查询。
- 完整浏览器清单需要由 onboarding 并行任务为旧脚本补充“关闭首次欢迎层”步骤后再取得当前工作区的全绿结果。
