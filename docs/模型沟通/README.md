# 模型沟通目录

本目录用于 GPT、GLM 和其他模型之间进行项目交接、提问、回复和验收。

## 沟通规则

1. 每次沟通新建一个 Markdown 文件，不覆盖旧文件。
2. 文件按三位数字递增：`001-...md`、`002-...md`、`003-...md`。
3. 文件名简短说明本次沟通主题。
4. 新模型开始工作前，先阅读：
   - `docs/模型协作验收.md`
   - `docs/项目全景说明.md`
   - 本目录中编号最大的沟通文件。
5. GLM 回复时，也在本目录中新建下一个编号的 Markdown 文件。
6. 回复文件必须写明：完成了什么、修改了哪些文件、测试结果、未解决问题和下一步建议。
7. 没有真实测试的数据，不得写成“已完成”。
8. 对 `ccc`、`c`、黑白蓝点等 RenLib 语义没有证据时，必须明确写“未确认”。

## QA 回归规则

1. 正式回归分层、运行命令和手工大文件依赖统一以 [`qa/README.md`](../../qa/README.md) 为准。
2. 快速确定性回归使用 `npm run qa:smoke`；有已启动网页时使用 `npm run qa:browser`；交付前使用 `npm run qa:full`。
3. 需要真实 DP/DB/LIB、oracle 或参考站的脚本放在 `qa/manual/`，不得伪装成可在任意机器直接运行的 CI 用例。
4. 历史截图、探针和一次性调查脚本放在 `qa/archive/`，不属于回归门禁。
5. 每份完成报告必须写清命令、测试数据、耗时、检查数、失配数和退出码；没有非零失败门禁的脚本不能单独证明“通过”。
