# 044 - GPT 完成 DP/DB 数据库兼容与验收

日期：2026-08-27
分支：`codex/features`

## 本轮完成

- 确认用户文件 `九天指南v5-1.db` 不是 SQLite，而是 LZ4 Frame 包裹的私有 DP/DB 棋谱数据库。
- 导入入口支持 `.db`、`.dp`，解析 `@BTXT@` 记录和 `1–9/A–F` 两字符 15 路坐标。
- 多条记录按共同前缀合并成变化树，并保留可识别节点文字。
- 支持 LZ4 独立/关联区块和未压缩区块；截断、错误回溯、错误区块尺寸和未知格式会明确拒绝。
- 增加 64MB 解压安全上限，避免损坏或恶意压缩文件卡死浏览器。
- 修复无效短记录先污染变化树、之后才被统计为跳过的问题；节点 ID 改为确定性生成。

## 自动化验收方法

1. 构造最小 LZ4 Frame，同时用 `.db`、`.dp` 两个扩展名导入。
2. 验证共同首手只生成一个根分支，后续两条记录生成两个变化。
3. 验证坐标、黑白交替、节点文字及跳过短记录提示。
4. 构造非 LZ4 和缺少结束标记的文件，验证明确失败而不是空导入。
5. 用 375×812 手机视口上传真实文件，等待本地棋谱库写入，再同时检查页面标题、节点数、根分支和页面运行错误。
6. 继续执行 SGF 高级导入、打谱保存/删除/刷新/导出回归，防止新格式影响原流程。

## 真实样本结果

- 文件：`九天指南v5-1.db`（54,759 字节）。
- 导入格式：`DP/DB LZ4 棋谱数据库`。
- 生成：1 份棋谱，3,158 个节点。
- 页面与脚本导入均成功；三条提示分别说明有效记录合并、无效记录跳过及节点文字保留。
- 早期约 3,172 节点的统计包含被跳过短记录留下的污染节点，修复后 3,158 才是当前正确结果。

## 兼容边界

这是对已确认样本结构的兼容，不是对所有名为 `.db/.dp` 的私有格式作无条件保证。当前记录按“从黑棋开始、逐层交替”恢复颜色；在没有官方规范或更多样本前，不臆测未确认字段。其他软件或版本若使用不同 LZ4 内容结构，会明确提示不兼容，不静默生成错误棋谱。架构决策见 `docs/adr/0004-dp-database-import.md`。
