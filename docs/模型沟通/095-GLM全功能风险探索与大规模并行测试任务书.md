## 0. 给 GLM 主任务的总指令

这是一次面向当前共享工作区的“全功能、组合风险、兼容性”独立复核。额度允许时，请派生多个相互独立的子任务并行执行，但不要让多个子任务共享浏览器 context、测试数据、截图目录或可变存储。

测试重点不是只确认入口存在，而是寻找以下类型的缺陷：

1. 新功能只更新了一个界面，旧入口、快捷中心、手册、备份、导出或分享没有同步。
2. 单独使用正常，和主题、棋盘、棋子、透明度、字号、旋转、镜像、读谱、做题或 AI 规则组合后失效。
3. 画面能看到，但文字对比度、标注、手数、最后一手、禁手、候选点或胜线被材质遮蔽。
4. 状态切换、异步 Worker、取消、后台、切谱、刷新或恢复后，旧任务迟到写入新局面。
5. 页面提示“已保存、已恢复、已导出”，但实际持久化内容、导出范围或恢复结果不完整。
6. 现代浏览器正常，Chrome/WebView 83、Android 8、减少动效、低内存、存储不足或离线环境退化。

请把源码审计结果当作“风险假设”，必须用运行证据或明确的静态证据独立确认。不得仅因已有自动化全绿就写“无问题”。

## 4. 并行执行架构

### 4.1 推荐角色

- 1 个 GLM 主协调任务：只负责调度、去重、门禁和总报告。
- 24 个独立测试子任务：T00–T23。额度充足时可全部建立，但本机同时活跃建议控制在 6–10 个浏览器任务，防止 CPU/内存争用制造假超时。
- 1 个最终一致性复核任务：在各子任务结束后读取报告，不复用它们的浏览器状态。

### 4.2 波次

1. Wave 0：T00 基线和环境，只执行一次。
2. Wave 1：T01–T05 最新外观、标注、预览、主题、响应式，可并行。
3. Wave 2：T06–T14 编辑、读谱、研究、AI、规则、做题，可并行。
4. Wave 3：T15–T22 导入、大型谱、导出、资料安全、兼容与韧性，可并行。
5. Wave 4：T23 跨功能变形测试和最终一致性对账，等待前面任务完成后执行。

### 4.3 隔离规则

每个子任务必须：

- 新建独立 browser context，使用 `GLM2-Txx-` 数据前缀。
- 使用独立证据目录 `qa-artifacts/glm-2026-09-02-deep/Txx/`。
- 记录 context 名、浏览器版本、OS、URL、视口、deviceScaleFactor、主题、减少动效、触控状态。
- 启动时保存 localStorage 键名清单、IndexedDB 数据库清单；结束时保存 diff。
- 收集 `console.error`、`pageerror`、未处理 Promise rejection、失败请求和 Worker 错误。
- 结束时关闭 context；不能调用 `localStorage.clear()` 影响其他 context 或用户正在使用的页面。
- 同一缺陷只保留一个主编号，其他任务引用该编号。
- 运行固定写入 `artifacts/` 的现有脚本时，必须使用独立 sandbox/CWD；做不到时必须串行，禁止同目录并发覆盖证据。
- 主任务先生成源码快照 SHA-256 清单（排除 `node_modules`、`dist`、`artifacts`、`qa-artifacts` 和临时目录）。每个子任务结果都记录同一个快照摘要，防止把不同源码状态混成一份报告。

- 颜色：黑、白、红、蓝、绿色标注；确认高亮不改变原始标注颜色和内容。

- 检查滤镜是否裁边、糊字、吞掉形状内部、让点击区域变化或显著降低滚动/落子帧率。
- 读谱本机标注和打谱原谱标注都要测；取消标注模式不能清除已画标注。
- 选择后刷新、备份、恢复，再验证值；旧备份缺字段应恢复为无。
- 明确判断中性变化点、AI 候选、最后一手是否属于产品所称“标注”，并记录当前实际覆盖范围。

### T03｜卡哇伊、雪晶与组合预览一致性

- 卡哇伊必须明显为粉色小猫与薄荷青搭档，不得退回黑粉/白粉或出现“黑不黑粉不粉”的脏色。
- 雪晶必须有深冰晶和浅霜晶的两方差异，结冰切面、雪花和冷光可见。
- 5、9、15、19、21 路分别落至少 6 手；检查棋子缩放后五官/切面不会出圈或成为噪点。
- 显示手数开/关、最后一手、注释角标、书签、胜线、透明度 40/72/100%、旋转和镜像组合测试。
- 棋盘透明度预览和棋子透明度预览都必须随当前棋盘、棋子和两种透明度同步更新。
- 对比预览与真实 SVG：颜色、双方含义、造型、透明度方向不能相反。
- 切换材质 50 次并快速拖动滑杆，检查旧伪元素、旧材质 class、延迟状态或内存增长。

### T04｜跨主题文字、按钮和状态可读性

### T11｜交换、五手打点、塔十与塔拉开局状态机

- 网络/Worker 慢、失败、重复完成时，状态栏不能永久卡住。

### T23｜跨功能变形测试与最终一致性对账

该任务必须等待 T01–T22 结束，再选取已通过场景做组合序列：

1. 建谱 → 选深色棋盘 → 黑色标注 → 开蓝色高亮 → 旋转镜像 → 导出 PNG → 保存 → 读谱 → 本机标注 → 备份 → 清空 context → 恢复。
2. 五手多打 AI → 白4时打开规则说明 → 返回选 10 打 → 中止 AI → 切读谱 → 再开另一规则，检查旧状态不串入。
3. 大型谱读谱 → 快速导航 → 创建编辑副本 → 改注释和材质 → 分享 → 撤销 → 放弃 → 回到原大型谱。
4. 做题有禁 → 切无禁题 → 返回打谱自由规则 → 开 AI 有禁规则，确认禁手状态只跟当前模式/规则走。
5. 自定义深背景 + 最低棋盘/棋子透明度 + 特大字号 + 减少动效 + 360px，完成保存、树导航和退出弹层。

最终对账必须覆盖：

- 设置页、快捷中心、刷新、备份恢复后的选项和值一致。
- 规则目录、问号说明、规则总说明、手册、元数据、选择器、分享图的规则名一致。
- 打谱可编辑、读谱只读+本机标注、做题独立进度不串写。
- 自动演示入口只在读谱存在。
- 普通谱和大型谱在选择器、文件夹、最近会话、导出和恢复中的身份/计数一致。
- 所有成功 toast 都有真实数据或文件证据。

## 7. 缺陷分级

- P0：数据丢失/串谱、备份恢复破坏、错误覆盖、旧异步任务写入新局面、规则反向判胜。
- P1：核心流程不可完成、读谱能改原谱、有禁/无禁错误、关键视口无法操作、导入/导出内容错误。
- P2：设置/快捷/手册/分享未同步、特定主题标注或文字难辨、布局溢出但有绕行、旧 WebView 关键功能退化。
- P3：轻微视觉、措辞、非阻断动效、细小对齐或仅装饰性差异。

同一缺陷只设一个主编号，格式 `BUG-GLM2-领域-序号`。

## 9. 总报告最低要求

GLM 主任务最终必须提供：

1. 实际测试文件数、单测数、正式浏览器脚本数、探索任务数、场景数、断言数。
2. 浏览器/视口/主题/棋盘/棋子/高亮/规则覆盖数量。
3. console error、pageerror、failed request、Worker error、长任务数量。
4. 缺陷按 P0/P1/P2/P3 去重后的数量。
5. 条件阻塞数量及解除条件。
6. “功能域 × 平台/视口 × 结果”矩阵。
7. “风险假设 H01–H36 × 已证实/已排除/条件不足”矩阵。
8. 所有证据的绝对路径。
9. 历史 6 项缺陷的防复发结果，但不重复计数。
10. 最终结论：可发布、带已知 P2/P3 接受发布、不可发布、条件不足无法判断。

机器汇总不得只依赖人工 Markdown。每个子任务同时生成 `task-result.json`，至少包含：`taskId`、`runId`、`sourceSnapshotHash`、环境版本、开始/结束时间、确切命令、退出码、用例总数/执行/通过/失败/阻塞/跳过、正式脚本实际 ID、错误计数、输入/下载 SHA-256、证据路径和最终状态。状态只能是 `PASS`、`FAIL`、`BLOCKED`、`INVALID`；计数不守恒或缺少实际执行清单时判 `INVALID`。

P0/P1 缺陷必须由第二个 clean context 或独立 sandbox 复现。重跑通过不能覆盖首次失败；必须保存首次证据并给出 N/M 复现率。测试基础设施故障使用 `TEST-INFRA-*` 编号，不得登记成产品缺陷。

禁止无证据写：

- “所有功能都没有 bug”。
- “应该兼容 Android”。
- “最新源码已经安装到手机”。
- “有禁/无禁生效”（没有实际棋形和结果）。
- “大型谱通过”（没有真实文件大小、节点数、路径和内容校验）。
- “分享/备份/导出正常”（只看到 toast，没有检查文件或恢复内容）。

由于本任务禁止 Android 构建和安装，Android APK 与真机结论必须保持“本轮未验证”。
