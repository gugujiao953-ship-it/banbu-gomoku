# 060｜轻量音效引擎、设置与性能验收

日期：2026-08-29  
对应任务：VFX-01、VFX-02、VFX-03

## 结论

采用 Web Audio API 程序化合成，不引入 MP3/WAV、第三方音效库或常驻 Worker。黑白落子使用频率、衰减和敲击噪声略有差异的短音色；导航、成功、警告和错误使用短促提示音。生产包没有新增音频资源，音频上下文按首次用户交互创建并全局复用。

## 选择依据

- MDN Web Audio 最佳实践：音频上下文应在点击等用户手势内创建或恢复，避免自动播放策略拦截。
- Chrome 自动播放策略：用户交互前创建的 `AudioContext` 可能处于 `suspended`，交互后需要 `resume()`。
- W3C Web Audio：使用音频节点图进行合成；本实现只使用 Oscillator、Gain、BiquadFilter 和极短的内存噪声缓冲。
- MDN `AudioContext.close()`：应用卸载时关闭上下文，释放系统音频资源。

## 设置能力

设置页新增“声音与反馈”：

- 总音效开关。
- 落子与导航音开关。
- 结果与警告音开关。
- 0–100% 音量滑杆。
- 落子、完成、警告三个试听按钮。

设置存入 `banbu-sound-settings-v1`，刷新后恢复，并进入一键备份/恢复。关闭总音效或把音量调为 0 时不会为播放创建新的节点；未创建上下文前关闭音效也不会主动创建上下文。

## 资源与性能边界

- 音频文件：0 个，资源增量 0KB。
- 新依赖：0 个。
- 全局最多复用 1 个 `AudioContext`。
- 同时活跃声音上限：8；超限事件直接跳过，防止快速点击堆积。
- 落子声约 75ms，其他提示声约 45–140ms。
- 每个临时音频节点结束后断开；应用卸载时关闭上下文。
- 不使用循环、定时背景音乐、麦克风、网络请求或音频解码。
