# 第 15 次模型沟通：分支选点文字必须显著放大

时间：2026-08-26  
发送方：GPT（转达用户最新明确要求）  
优先级：P1，与“原谱文字去圆框显示”一起验收

## 用户要求

棋盘上的分支选点文字目前太小，手机上看不清。不是把 `7px` 微调到 `10px` 就够：**文字至少要比当前大两倍多，接近一颗棋子的视觉大小也可以。**

用户接受文字占位明显，只要能一眼识别；不要为了“精致”继续做成小圆点里的微小字。

## 已有实测基线

《雨》谱 412×915 浏览器验收中，原谱文字 `#`：

```text
当前字号：7px
当前样式：白色圆点 + 7px 蓝色文字
结果：手机尺寸下几乎不可辨认
```

截图：`artifacts/renlib-display-rain-412x915.png`。

## 实施要求

1. 对 `displayKind=text` / 原谱文字：**不绘制底层圆点或圆框**，直接绘制文本。
2. 单字符（如 `#`、`a`、`c`、字母、汉字）SVG 字号应为 **20–24px**；当前棋子直径约 31px，这一范围接近单颗棋子的视觉大小，且超过当前 7px 的两倍。
3. 两字符文字建议 18–20px；三至四字符可降至 14–17px，但不能回到 7px，也不能因过小而失读。
4. 使用 `paint-order: stroke`、浅色描边/深色文字或反向组合，保证木纹棋盘上的对比；颜色不应只依赖蓝色细字。
5. 文字保持 `pointer-events:none`；棋盘原有约 34px 透明点击热区不能因取消圆框而缩小。
6. 有文字的点不得再同时具备 `.renlib-variation-dot`。无原谱文字的中性候选点才可使用小圆点。
7. 已落子的位置不叠加分支文字。旋转、镜像、显示手数开关后，文字位置与读写性仍正确。

## 建议实现方式

在 `Board` 中按 `displayKind` 分支渲染，而不是“先画 circle、再可选画 text”。对文本长度增加样式类，例如：

```tsx
const glyphs = Array.from(displayText);
const textClass = glyphs.length <= 1 ? "renlib-text-single"
  : glyphs.length === 2 ? "renlib-text-double"
  : "renlib-text-compact";
```

对应 CSS 可从以下级别起步，最终以真机截图校准：

```css
.renlib-text-single  { font: 800 22px ui-monospace, monospace; }
.renlib-text-double  { font: 800 19px ui-monospace, monospace; }
.renlib-text-compact { font: 800 15px ui-monospace, monospace; }
```

这些是原谱文字点，不是普通棋谱标注，因此不要复用 `.board-label` 的圆形背景。

## 验收标准

在 360×800 和 412×915 中：

- 单字符计算后字号不低于 20px；
- 原谱文字点 `hasDot === false`；
- 单字符肉眼可从棋盘一臂距离清楚读出；
- 深/浅文字都能与木纹棋盘区分；
- 无横向溢出、无被棋子遮住、点击正常；
- 将新的截图与 `artifacts/renlib-display-rain-412x915.png` 对照，视觉大小和可读性有明确提升。

注意：此要求不能仅修改 CSS。必须先完成第 14 次沟通所列 raw/displayKind 解析与渲染接线；否则只会把所有分支点的伪样式一起放大，仍然不符合“原谱怎么显示，网页就怎么显示”的目标。
