## 当前判断

当前卡顿的主要原因不是单一的 Proxy 属性访问，而是多个隐式全量操作叠加：

- `Object.values(document.nodes)` / `Object.keys(document.nodes)` 触发整树物化。
- `children.slice()`、`map()`、迭代器触发大量兄弟节点物化。
- React 主组件依赖整份 `document`，导航时造成不必要的级联重渲染。
- `boardAt()` 在缓存未命中时沿根路径重放棋盘。
- Worker 之前将完整节点对象树通过 `postMessage` 回传主线程。

爱五子棋内部实现没有可公开、可独立验证的索引和缓存证据，因此不能把具体实现推断写成逆向事实。当前采用的是面向相同产品目标的工程架构：稳定索引、按需节点、窗口化分支和局部棋盘缓存。

## 已完成

### 1. Worker 结果协议改造

大型 `.lib` 解析结果不再把完整 `GameDocument.nodes` 作为最终结果回传主线程：

```text
Worker 解析
  -> compact index + 元数据 + 警告
  -> 主线程 createLazyDocument()
```

主线程仍获得兼容的 lazy `GameDocument`，保存和 UI API 不变。

### 2. compact index 查询 API

新增或使用：

- `compactNodeIndex`
- `compactChildCount`
- `compactChildAt`
- `compactChildWindow`
- `compactSearch`
- `createLazyDocument`

大型分支面板不再通过 `branchView.children.slice(start, end)` 取窗口；棋盘后续变化点也不再默认读取 `pivot.children.slice(0, 513)`。

### 3. 查找和导航优化

- 大型 lazy 文档查找直接扫描 compact index 的坐标、文本引用和评价编码。
- `Board` 组件 memo 化，减少无关状态造成的 SVG 重绘。
- `boardAt()` 增加父节点棋盘增量缓存。
- 导航或切谱时清除待放置的候选标签，避免跨节点误标注。

### 4. 导入统计字段

`ImportResult` 增加可选 `stats`：

- `nodeCount`
- `edgeCount`
- `branchCount`
- `maxChildren`
- `maxDepth`

当前解析过程中同步维护这些统计，避免单独依赖 `Object.values` 做统计。
