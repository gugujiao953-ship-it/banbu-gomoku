## 二、实现

1. 新增 `src/backup.ts`，定义 `banbu-gomoku-backup`、版本 1 的 JSON 备份格式，包含 `schema`、`version`、`appVersion`、`exportedAt`、白名单 localStorage 数据和大型棋谱 IndexedDB 数据。
2. 大型 IndexedDB 数据通过 `src/large-storage.ts` 新增的结构化记录接口导出/恢复，不在备份中写入原始 LIB/DP/DB 文件，也不读取或序列化默认导出目录的 `FileSystemDirectoryHandle`。
3. 对 ArrayBuffer 和 typed array 做 Base64 结构化编码，避免 JSON.stringify 将大型紧凑索引中的二进制数组变成空对象。
4. 恢复前校验 schema、版本、时间、棋谱树、题库、文件夹、草稿、摘要、分块索引等结构；解析和校验失败时不写入任何现有数据。
5. IndexedDB 恢复使用单个 readwrite transaction 清空并写入四个 store；若后续 localStorage 写入失败，会用恢复前快照回滚大型 IndexedDB 和 localStorage。
6. 设置页“数据与兼容”区域新增“一键备份”和“恢复备份”入口。备份默认写入用户选择的导出文件夹，目录写入失败时回退到浏览器下载目录；恢复成功后自动重新加载页面以刷新应用内状态。
7. 新增 `renju-note-display-settings-v1`，使显示手数、显示坐标、禁手辅助设置可持久化并纳入备份。

## 五、边界

1. 当前交付格式是可读、可校验的 JSON，尚未引入 ZIP 压缩。大型索引备份可能较大，后续如遇移动端内存压力再评估流式 JSON/ZIP 或分块下载。
2. 默认导出目录的权限句柄不随备份迁移；恢复后仍需在当前设备重新选择目录。
3. 恢复采用完整替换语义，不做跨版本合并；备份文件中的 ID 会原样恢复，重复恢复不会产生重复记录。
4. 内置开宝题库是静态资源，不重复写入备份；仅恢复用户自定义题库、进度和标题覆盖。
5. 已打开的原始 LIB/DP/DB 文件字节不在应用存储中伪造回写；备份保留的是应用已建立的结构化大型棋谱数据。
