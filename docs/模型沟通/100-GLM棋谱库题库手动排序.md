# 100｜GLM 棋谱库/题库手动排序与排序菜单

日期：2026-09-03
对应诉求：棋谱库与题库中的文件夹、棋谱、题集、题四层均无法手动排序；要求加拖拽排序 + 排序按钮（A→Z、默认等），UI 符合整体风格。

## 数据模型

新模块 `src/library-order.ts`（纯函数 + 6 个单元测试）。顺序以"每容器的 id 列表"存储在 `libraryFolders.order`（随现有键持久化、随备份走）：

```
recordFolders:   父文件夹路径 → 子文件夹路径顺序
puzzleFolders:   同上（题库侧）
records:         文件夹路径 → 棋谱/大型棋谱 id 顺序
puzzleCollections: 文件夹路径 → 题集 id 顺序
puzzles:         题集 id → 题目 id 顺序
```

**缺省即自然序（插入顺序）**——所以"恢复默认排序"就是删键，完全可逆；`applyOrder` 与自然 id 求交集，孤儿/陈旧 id 无害。文件夹重命名会同步重映射 order（`remapFolderOrder`）；删除题集会清理对应桶（`removeFromOrder`）。备份校验接受可选 `order`（`isLibraryOrderMaps`），旧备份无此字段照常恢复。

## UI

- 每个文件夹头部新增排序按钮（ArrowDownUp）：子文件夹 A→Z / Z→A（有子文件夹时）、内容 A→Z / Z→A、恢复默认排序；弹出菜单用语义 token，风格与库页一致。
- 题集工具行新增排序按钮：题目 A→Z / Z→A / 恢复默认。
- 拖拽（HTML5 DnD）：文件夹头、棋谱卡、题集卡、题目行均可拖动，仅限同容器内重排（跨文件夹移动仍走原有的下拉/批量移动）；拖动经过时显示上/下插入指示线。
- 题目行与题集卡新增 GripVertical 拖拽把手——按钮会吞掉 dragstart，把手是可靠的拖拽起点。
- 题目在管理列表中的显示序 = 自定义序；打开题目仍按题集内自然索引，不受影响。

## 过程中发现并修复的既有缺陷

- **React DOM 崩溃**：列表重排的同一次提交里挂载 toast 会触发 `insertBefore NotFoundError`（ErrorBoundary 兜底成整页错误）。根修：`AppToast` 改为常驻挂载（无消息返回 null）——这同时是 aria-live 区域的可访问性最佳实践。排序提示延迟到下一帧（`announceOrderToast`）。
- 排序/恢复默认在**未过滤的全量容器**上计算，搜索状态下拖拽/排序不会冻结被隐藏的条目。

## 已知边界与备注

- HTML5 拖拽是鼠标手势，触屏上不生效——移动端用各处排序菜单（本题库目标设备以触屏为主，菜单已覆盖全部排序需求）。
- 拖拽把手在 headless Chromium 下不产生 drop（Playwright/Chromium 小元素拖拽怪癖），验证脚本对题目行用合成 DragEvent 驱动处理器；记录卡真实手势已验证同一管线。
- `npm run build` 的 `tsc -b` 在本任务收尾时被并行会话新加的 `src/features/vcf/vcf-generator.test.ts` 类型错误阻塞（非本任务文件）；`vite build` 产物已验证。该文件恢复后跑一次 `npm run build` 即可闭环。

## 修订 2（2026-09-04，用户反馈：UI 过大 + 触屏不可用）

1. **UI 对齐本地规范**：新增控件原先用了 38×38 的 `.library-inline-action`，比所在行的 29px 紧凑规范"巨大"且突兀。修订：文件夹行按钮 32×32、题库工具行排序按钮 29×29 与同行齐平；排序弹层收紧（128px 最小宽/32px 行高）；文件夹标题与题集行全部 `nowrap + ellipsis` 不再换行；拖拽把手统一 13px。
2. **触屏拖拽**（`src/library-touch-drag.ts`，文档级委托）：
   - 长按 220ms 抬起条目（幽灵卡片跟随、轻震动、原位置半透明占位）；轻扫（未达长按即移动 >12px）仍是正常滚动。
   - 双指并行：拖拽激活后第二指位移换算为滚动（手动 scrollTop，带钳制），实现"一指拖、一指滚"。
   - 边缘匀速自动滚动：手指停在视口上下 76px 区间时以 300px/s 匀速滚动；**三级边界钳制**——棋谱/题集只滚到本文件夹列表底部（不会滑出文件夹）、文件夹滚到父级底部、顶层滚到页面底部；双指手动滚动同受钳制。
   - 落点复用 `performLibraryDrop`（与鼠标同一套 moveRelative + order map），批量选择模式禁用。
3. 验收：`verify.mjs` 全项 ALL PASS（新增触屏长按拾起/双指滚动/触摸重排/边缘自动滚动含钳制断言）；Vitest 333/333；vite build 8.15MB/20MB；对比度静态审计 + 20 主题运行时扫描 0 命中。
4. 注：`browser.close()` 在本机偶发挂起，verify.mjs 改为先输出结果再强退；headless 对把手小元素不派发原生 drop，触屏拖拽用合成 TouchEvent 验证（处理器与原生路径同一入口）。

## 修订 3（2026-09-04，用户反馈：题库出现白色方块 + 棋谱库补回把手）

- **根因**：修订 2 在题库行/卡插入把手 `<span>` 后，原 CSS 的 `button:first-child`（开卡/开题按钮的 flex 布局规则）因把手成为首子而失效，按钮回退为浏览器默认样式（2px outset 边框的白方块、内容竖排）——即用户看到的"白色正方形包住名字和信息"。改为 `button:first-of-type` 后恢复横排无框布局，与棋谱行一致。
- **一致性**：棋谱库每条棋谱（含大型棋谱）行首同样加入 `⋮` 拖拽把手；题库题集卡与题目行支持整卡/整行长按拾起（把手保留为视觉暗示与精确起点）。两端功能一致：长按拾起 / 幽灵跟随 / 插入指示 / 双指滚动 / 边缘匀速自动滚动（三级钳制）。
- **教训（已写入记忆）**：在既有容器首个子元素位置插入节点前，必须 grep 该容器相关的 `:first-child` / `:last-child` 规则——本项目里这类规则被反复用作"主按钮"选择器。
- 验证：`verify.mjs` ALL PASS（记录把手拖拽、题集卡长按、双指滚动、边缘自动滚动钳制等全链路）；Vitest 333/333；vite build 8.15MB/20MB；静态审计 + 20 主题扫描 0 命中；截图确认棋盘卡与题集卡横排统一。

## 修订 4（2026-09-04，用户反馈：题库未完全适配主题，白底发光）

- **根因**：题库「文件夹下拉框 + 管理按钮」所在的 `.puzzle-collection-tools select`/`button` 及记录卡的 `.record-info select` 在 library.css 里写死浅色 `#f8f6f1/#f0f6f2/#ded8ce`。文件末尾的主题化兜底块用的是 `:where(...)`（特异性 0），会被这些具名规则压制，所以暗色主题下仍"白得发光"。
- **修复**：把这几处控件背景/边框/文字直接改为语义变量 `background: var(--surface-3); border-color: var(--surface-border); color: var(--muted)`（按钮文字 `--green-2`），从源头融入主题，而非依赖零特异性兜底。
- **一致性**：题集卡与记录卡的文件夹下拉框现在同一配色来源；`題` 角标保留强调色（与记录卡 mini-board 的木纹角标同类，属有意点缀，非文字底）。
- **验证**：dark / eye / blackgold 三主题截图确认无白块；运行时对比度扫描 `sweep.mjs` 全 20 主题 0 命中（`--muted` 文字落在 `--surface-3` 上各主题均 ≥4.5）；Vitest 333/333；vite build 8.15MB/20MB。
- **教训**：主题兜底不要只靠 `:where()`——遇到组件级具名颜色规则会失效；控件配色应在组件规则里就用语义变量。
## 修订 5（2026-09-04，用户反馈：管理面板白茫茫 + 行内“排序按钮”点了没反应）

- **管理面板未适配主题**：`.puzzle-manager-list`（列表底/分隔线）、题号方块 `button span`、重命名按钮、`.rename-summary`/`.folder-empty` 全部写死浅色（#faf8f4/#efebe4/#ece8df/#7d7569/#7e776d/#ece7df）。改为语义变量：列表底 `--surface-3`、分隔线 `--surface-border`、题号方块底 `--jade` 文字 `--green-2`（各主题 7.7–11.3:1，远超 4.5）。dark/kawaii/porcelain/eye 四主题截图 + 程序化对比度均确认。
- **“点了没反应”的澄清**：每行左侧的 ⋮ 是**拖拽把手**（只能拖不能点），右侧 ✏️ 是**重命名**；真正可点的排序在工具行 ⇅（题目 A→Z / Z→A / 恢复默认），功能正常。为消除“死按钮”观感，把手加宽到 16px、`cursor:grab`、按下变强调色，并保留整行长按拖拽。
- 验证：verify.mjs ALL PASS；Vitest 333/333；vite build 8.15MB/20MB；静态审计 0 + 20 主题运行时扫描 0（含管理面板题号对比度单独复核）。
- **顺带同类修复（用户“多看看类似情况”）**：同法把定位搜索 `.position-search-entry`、`.match-toggle`、题库手风琴 `.collection-accordion-body`、内联工作区 `.inline-record-list`/`.inline-collection-list`/`.inline-puzzle-list`（含 current 态与题号 span）共 9 处写死浅色，改为 `--surface/--surface-3/--surface-border/--jade/--green`；`amber` 角标（position-search 图标、storage-icon.folder）作为有意点缀保留。
