## 一、任务

加强图片识谱：以五子棋小工具（renjutool `CheckerBoard/image2board.js`）与开宝的图像识题为参照，调研最新方案后择优实现。目标分两级：先做到棋盘棋子位置与颜色零误差；进阶做到带序号截图可复刻落子顺序。验收标准：拿棋谱截图（含较多标注文字的局面）走真实导入流程，准确率 >90%。

## 二、技术选型

- 调研结论（来源：Kifu-snap、gbr、Kifubara、CEUR 网格识别论文等）：**正面截图场景下，"网格线定位 + 交叉点采样分类"的传统 CV 就是最优解**；深度学习（YOLO/Pix2pix）优势在斜拍、真实棋盘照片、强光反射等复杂输入，对截图输入属于过度设计且需要随包分发模型。
- renjutool 的实现依赖**用户手动框选棋盘四角**保证对齐，识别本身只是颜色分类。本项目在此基础上前进一格：**全自动定位网格**，无需手动框选。
- 最终方案：增强型传统 CV，零依赖、无模型文件。

## 三、实现（src/image-recognition.ts 重写 + src/App.tsx 落盘逻辑）

1. **网格自动定位**：对每行/列统计"亮-暗-亮"翻转计数（细暗线夹在两侧亮色之间）。该特征与整体曝光无关（页面白背景会把暗阈值法带偏），棋子边缘不满足模式（内侧也是暗的），粗边框用相对阈值（±22）覆盖。检出线用最小二乘精化等差序列（整数 gap 会量化间距、在 512px 上累积漂移），相位从每个检出线外推，coverage 最高者胜。wood 包围盒（检出线矩形内亮度众数 = 木色，木色占比 >60% 的行/列范围）约束序列的首尾——这是"边框首线漏检时序列应上移一格"的唯一可靠信号。杂散 UI 分隔线只损失 1 个 coverage 点，不会否决整个棋盘。
2. **棋子分类（关键创新）**：多数投票改为**饱和度+亮度两级分类**。黑白棋子是中性灰（饱和度 <45），木色棋盘是强彩色（饱和度 ~111）——先按饱和度剔除棋盘底色，再在低饱和像素内按亮度分黑白。旧的纯亮度法在"灰白棋子渐变（亮度 128–190）+ 米色棋盘（178）"上必然失败：两者亮度区间重叠，白子 72% 的像素落进"不暗不亮"死区。此为本次最大的一类错误的根因。
3. **背景亮度**：改为**网格覆盖区域内**的中位数。旧的全图中位数会被页面白背景带偏（239 vs 真实木色 178），导致整个棋盘被判"暗"、空点批量误报为黑子。
4. **序号识别（进阶）**：棋子中心按 5×7 点阵模板做多尺度模板匹配（0.9/1.0/1.15/1.3 倍），单位与两位数分别识别，阈值 0.72/0.76。**安全护栏**：只有当识别出的序号恰好构成完整连续序列 1..N 且数量等于识别子数时，才按序号重建走子链（可用手数、悔棋等打谱功能）；有任何缺号/重号则回退为静态局面导入，避免一个误读数字打乱整盘历史。
5. UI 提示文案从"目前准确率很低，识别后请务必人工校对"更新为如实描述新能力。

## 五、调试过程中定位并修复的真实问题（按因果链）

1. 网格线被棋子遮挡 → 只用边缘可见线做相位外推（最少 4 条线即可定 spacing+origin）。
2. 整页截图里页面白背景使"暗像素"阈值失效 → 改为亮度无关的"亮-暗-亮"翻转特征。
3. 竖线沿垂直方向是"暗-暗-暗"，翻转方向必须按行/列分别取横/竖。
4. 整数间距量化漂移 → 最小二乘精化，且精化后 coverage 下降则回退（防杂散分隔线拖偏回归）。
5. UI 分隔线（y=1519）混入检出线：wood 采样矩形被拉到全页导致众数变白、90% inside 门槛否决真解 → wood 范围用最小 gap 限制 + 门槛 75%（coverage 门槛本身已保证拟合质量）。
6. 首行边框粗线漏检 → wood 包围盒双向 walk。
7. 白子在"灰白渐变 vs 米色棋盘"上亮度重叠 → 饱和度两级分类（本次最大的单一修复）。
8. TDZ（const 声明顺序）导致整次识别直接抛错——toast 显示 "Cannot access 'a' before initialization"。

### 补充（同日）：内嵌浏览器无法导入图片的修复

用户在内嵌浏览器中导入截图毫无反应。根因：选完文件后代码调用 window.prompt 询问棋盘路数，而内嵌 WebView 与部分移动浏览器禁用 prompt（返回 null），导入被静默跳过。修复：

1. 移除 window.prompt，改为自动尝试常见路数（15/13/19/9/17），保留识别子数 ≥6 的最早成功者，全部失败才报错；用户原图（28 手带手数截图）实测 15 路 28 子、置信度 95%、位置颜色全对。
2. 新增**粘贴导入**（截图工具 Ctrl+C 后在页面 Ctrl+V）与**拖拽导入**（把图片文件拖进页面），均走同一识别入口并受草稿保护拦截。
3. 文件选择器 accept 显式列出 png/jpg/jpeg/webp/gif/bmp/avif/heic 及 image/*。heic 等浏览器无法解码的格式会给出明确错误提示，不会静默失败。
