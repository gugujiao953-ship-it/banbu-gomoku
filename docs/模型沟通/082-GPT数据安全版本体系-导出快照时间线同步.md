# 082｜数据安全版本体系：导出语义、自动快照、修改时间线与可选同步

日期：2026-08-30  
任务：在现有本地优先棋谱/题库模型上补齐可测试的数据安全基础能力。

## 架构判断

- 现有 `record-export.ts` 已支持“整谱 / 当前变化 / 当前局面”，`backup.ts` 已支持 `banbu-gomoku-backup` v1 全库备份；本轮没有复制这些实现，而是在 `src/features/data-safety/` 增加统一的语义、版本和冲突抽象。
- 快照使用独立 localStorage 键保存轻量完整 `GameDocument`，自动去重、防抖、按对象保留近期版本、固定版本不自动清理，并在恢复前建立保护快照；存储失败返回空值，不阻断应用启动。
- 时间线从快照派生结构化事件与差异摘要，表达节点/分支、元数据、注释/标注和书签变化，不记录敏感配置或 UI 点击。
- 同步默认关闭。`SyncEngine` 先调用本地持久化，再访问 provider；没有真实后端时使用 `MemorySyncProvider` 做可测试接入点，不宣称已提供云同步。

## 数据模型与迁移

- `ExportEnvelope.schemaVersion=2` 明确 `scope`（当前分支、完整棋谱树、单个棋谱、资料库备份）、`purpose`（分享/恢复）、`format`、应用版本、导出时间、内容摘要、兼容信息与内容哈希。
- 解析器保留现有 `banbu-gomoku-backup` v1 兼容路径，并对新格式做稳定哈希校验；篡改或截断会在写入前拒绝。
- 快照记录包含版本 ID、对象 ID、时间、触发原因、摘要、schemaVersion、内容哈希、固定标记和完整文档。

## 同步边界与剩余风险

- 尚未接入真实云 provider、账号或凭据存储；关闭同步时不会发起网络调用。
- 当前快照 localStorage 上限默认为 6MB，超限时保留旧数据并返回失败；大型紧凑棋谱仍应由现有 IndexedDB/大型存储接入专用快照适配器，避免把百万节点树复制到 localStorage。
- 时间线目前提供纯函数与持久化 API，尚未把版本历史面板接入每个棋谱卡片；UI 接入应等待并行的设置/播放改动稳定后再做，避免冲突覆盖。
- 恢复时调用方必须提供原子 `apply`；模块会在失败时重新应用恢复前文档，但跨大型 IndexedDB 的事务级保护仍需后续适配。
