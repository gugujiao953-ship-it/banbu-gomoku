## 已完成修复

### P0：大型兄弟分支点击崩溃

大型 compact 文档的 `chooseChild()` 不再调用：

```ts
updateNode(document, pivotId, { preferredChildId: id })
```

避免对 lazy proxy 执行 `{ ...document.nodes }`，导致文档被截断。

大型文档现在点击分支只更新 `currentId`；普通小文档仍保留 preferredChild 更新逻辑。

Board 使用稳定 Hooks 顺序，并对无效 currentId 回退根节点，消除：

```text
Rendered fewer hooks than expected
Cannot read properties of undefined (reading 'children')
```

### 棋盘伪 A–Z 标签

删除：

```tsx
String.fromCharCode(65 + index)
```

现在：

- 没有原始文字时只显示中性变化点。
- 有 `boardText` 时显示原始短文本。
- 分支序号只保留在变化面板列表中。
- 不再用 A–Z 冒充原谱字段。

### IndexedDB 风险

- `documentFingerprint()` 对 compact 文档直接返回 compact 指纹，不遍历整棵树。
- `removeLargeDocument()` 清理 `DOCUMENT_STORE`、`SUMMARY_STORE` 和 `CHUNK_STORE` 对应分块。
- `assembleCompactIndex()` 恢复 marks，不再固定为空数组。
- chunk 读取使用 `IDBKeyRange.bound(id + ':', id + ':~')`，避免读取其他文档。
- 数据库版本升级并确保 `index-chunks` object store 存在。
- 大型 compact typed arrays 使用 ArrayBuffer chunk 保存。
- chunk 读取使用循环追加，避免 `push(...largeArray)` 调用栈溢出。

## 新增数据模型

新增 `src/renlib-display.ts`：

```ts
RenLibDisplayMark {
  rawText?
  rawMark?
  rawColor?
  semantic
  displayKind
  displayText?
}
```

映射约定：

- `a` → `good / text`
- `c` → `bad / text(c)`
- `ccc` → `bad / text(c)`，保留 rawText=`ccc`
- 黑 → `special / black-dot`
- 白 → `bad / white-dot`
- 蓝 → `special / blue-dot`
- 未知文字 → `unknown / text`
- 无文字 → `unknown / neutral-dot`

注意：这是用户指定的显示层约定。原始 RenLib 二进制字段的官方名称仍没有独立格式文档证据，因此 raw 值保留，未把 UI 语义伪装成官方格式结论。

## 仍需注意的性能事实

最新黑盒记录的最大 Long Task 仍可能达到约 7–10 秒，主要发生在：

- 22M 节点解析完成后的 chunk IndexedDB 写入/恢复。
- 首次 compact 文档 UI 状态建立。

导航本身仍保持接近一帧：

- P50 约 16–19 ms。
- P95 约 34–74 ms。
- 最大单步通常约 50–270 ms。

因此核心用户体验已达到可用验收，但若要求严格“导入期间完全无 7 秒级 Long Task”，下一步应继续将 chunk 写入拆为多个 IndexedDB 事务并把批次调度到后台，而不是改变解析/分支架构。
