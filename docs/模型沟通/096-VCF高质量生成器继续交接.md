## 五、已验证的正确语义护栏（不能破坏）

### 连珠黑方
- 成五优先于禁手。
- 长连（≥6）禁手。
- 双四按“4 子集合去重”：活四两端共享同 4 子只算一个四。
- 双三需判断活三的合法延伸，不能把非法延伸计为活三。
- 白方无禁手。

### VCF
- 进攻方每手必须是合法冲四；直四（两个成五点）终局；可直接成五终局。
- 防守方应手 = 冲四唯一堵点 + 防守方自身反击冲四；全部防守应手均失败才算 VCF 成立。
- 防守方已有成五点时，进攻方该分支失败。
- 每道生成题必须经过不同路径的独立复核器，不得仅用求解器自己的 line 复核。

## 六、下一步唯一推荐路线（不要再走独立线构造）

### 阶段 A：先建立语料分析，不要先生成

1. 读 `实战VCF_1052题.json` 的 1050 题。
2. 每题解析为 Int8Array；统计：黑/白子数、总子数、包围盒面积、密度、重心、最大棋子距离、方向/局部团簇。
3. 用当前求解器每题给严格时间预算（建议单题 50–200ms 首轮、再对潜在题延长到 2–5s），记录：
   - `win`
   - `aborted`
   - `depth`（进攻方实际手数）
   - `nodes`
   - `firstMoveCount`
   - `hasCounterFour`
4. 先不要把“题面落子数组”当答案；那只是局面摆子，必须由 solver 重新求解。
5. 生成 `vcf-generator/语料分析-实战VCF1052.md`，明确实际覆盖率。解不动就记未解，不伪造深度。

### 阶段 B：高质量素材优先采用“已解真题变形”，不要人工造平行线

对已解且 `depth >= 4` 的真题做安全变形：

1. 旋转/镜像（必须保留）。
2. 整体平移 1–3 格（不出界）。
3. 删除棋子：只删除经独立分析确认不参与任何解线/防守关键点的子；删除后重新求解+复核，深度仍 ≥4 才保留。
4. 添加棋子：只在远离解线、不会制造即时胜/破坏关键堵点处，黑白成对加；重新求解+复核。
5. 对称去重：局面 canonical hash 去重，避免只生成旋转副本。
6. 三档筛选：4–6、6–12、12–30；若语料没有足够深题，报告实际数量，不补假题。

这条路线的优点：真人编排的棋形、共享棋子关系、白方防守痕迹和自然分布直接保留；变形只是改变视角/布局，不会回到平行预制线。

### 阶段 C：如果真实题解覆盖不足

可采用“语料模板拼接”，但必须做到：
- 从真实题解中提取共享棋形关系图（黑子参与的四、白堵点、反击四）。
- 通过局部裁剪/旋转/平移嵌入同一棋盘，且至少两条冲四链共享 1–2 个黑子，不能是互不相干独立线。
- 每次嵌入后用 solver + independent verifier 复核。
- 默认不加入噪声；噪声只有在经过重解后才允许。
